# S3 storage for Mac and Windows

The S3 setup stores file blocks in a private bucket and uses PostgreSQL for the shared file index. JuiceFS provides the native mounts. Keep the database and bucket together when planning recovery.

## Mac only

Use the Mac as the only client and index host. Keep PostgreSQL on loopback and leave the Windows database login disabled. You need one AWS mount identity and no Tailscale connection.

Start with [AWS setup](#aws-setup) and [mount on the Mac](#mount-on-the-mac).

## Mac and Windows

Use both clients against the same S3 bucket and PostgreSQL index. By default, Windows needs the Mac awake and reachable over Tailscale. For independent access, configure the [optional hosted index](#optional-hosted-index) before mounting.

Start with [AWS setup](#aws-setup), then [mount on the Mac](#mount-on-the-mac) and [add Windows](#add-windows).

## AWS setup

Use AWS CLI v2, Python 3.10 or later, Terraform 1.9 or later in the 1.x series, a commercial AWS Region, and a provisioning profile for the account. Pick your account's assigned Region if your AWS project restricts Region selection.

### Create or identify the source sign-ins

Use one unprivileged, MFA-backed federated source sign-in per device. Each source can assume only its corresponding `project-drive-mac-mount` or `project-drive-windows-mount` role. The Terraform stack creates these mount roles with read and write access limited to the `project-drive/` prefix in its bucket. Keep your provisioning access outside the mount users' profiles.

For example, if you use IAM Identity Center, give each device's source sign-in a permission set with only `sts:AssumeRole` on its corresponding mount role ARN. Obtain the source IAM role ARN from IAM after assigning that permission set, then configure its AWS CLI profile with `aws configure sso`. Use the IAM role ARN in Terraform. Some AWS accounts need an external federation setup. [IAM Identity Center CLI configuration](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html) · [AWS project service availability](https://docs.aws.amazon.com/accounts/latest/reference/supported-services-sign-up-new.html)

### Review and apply a plan

Copy the example for your route to `infra/pilot/project.tfvars.json`. Use `mac.tfvars.json.example` for Mac only or `mac-windows.tfvars.json.example` for both computers. Fill in your account ID, Region and source role ARNs. You can add a Windows source role later and replan. Use an encrypted location for local state or configure your own protected backend before applying.

```bash
python3 tools/cloud.py check --vars infra/pilot/project.tfvars.json --profile provisioner
python3 tools/cloud.py plan --vars infra/pilot/project.tfvars.json --profile provisioner
# Review the Terraform plan before applying it.
python3 tools/cloud.py apply --vars infra/pilot/project.tfvars.json --profile provisioner
terraform -chdir=infra/pilot output -json
```

The default flow checks for an active AWS Free plan and remaining credits. Use `--minimum-days` and `--minimum-credits` for the duration and spend you expect. For an account where you deliberately accept standard AWS billing, add `--allow-paid` to each command. Both modes confirm the signed-in account matches the config. The apply command rejects saved plans with deletions or replacements.

In US East (Ohio), S3 Standard storage is about **$2.30/month for 100 GB billed for the full month**. Requests are metered. The first 100 GB of internet downloads per month is shared across your AWS usage, and the next tier in Ohio is $0.09 per GB. At 10 GB downloaded per day for 30 days, that is about **$20.30 for storage and transfer**, assuming the allowance is available. Account credits and taxes affect what you pay. The filesystem starts with a 25 GiB quota. S3 meters stored blocks, which can include old writes and trash. [S3 pricing](https://aws.amazon.com/s3/pricing/) · [Ohio transfer rates](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AWSDataTransfer/current/us-east-2/index.json)

### Configure the device profiles

For the Mac, create a source profile called `project-drive-mac-source` with your federated sign-in. Add the following entries to the device's AWS config and replace the sample account, Region and AWS CLI executable path. The session profile assumes the provisioned mount role. The second profile lets the JuiceFS AWS SDK get renewable credentials from the CLI.

```ini
[profile project-drive-mac-session]
role_arn = arn:aws:iam::123456789012:role/project-drive-mac-mount
source_profile = project-drive-mac-source
role_session_name = project-drive-mac
duration_seconds = 3600
region = us-east-2

[profile project-drive-mac]
credential_process = /usr/local/bin/aws configure export-credentials --profile project-drive-mac-session --format process
region = us-east-2
```

For Windows, use the corresponding `project-drive-windows` profile names and role ARN, and quote the AWS CLI executable path if it contains spaces. Verify each profile with `aws sts get-caller-identity --profile <mount-profile>`. Sign in with the source profile's MFA flow and let the SDK obtain short-lived credentials. Keep AWS keys out of the JuiceFS format, local configs and metadata exports. [AWS external credential processes](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sourcing-external.html)

## Mount on the Mac

Install JuiceFS v1.3.3 for your Mac architecture and macFUSE 5 or later. The script uses FSKit on macOS 15.4 or later. Enable the FSKit extension as needed. Use current PostgreSQL 16 updates from Homebrew. [JuiceFS releases](https://github.com/juicedata/juicefs/releases/tag/v1.3.3) · [macFUSE backends](https://github.com/macfuse/macfuse/wiki/FUSE-Backends)

For a Mac-hosted index, run these commands as the signed-in Mac user. Use a unique PostgreSQL password, which the mount script can read from a generic Keychain item named **ProjectDrive PostgreSQL**. Use the index hostname as the item's account.

```bash
brew install postgresql@16
bash scripts/index-mac.sh init
bash scripts/index-mac.sh password mac
```

In Disk Utility create an **encrypted APFS** volume named **ProjectDriveCache** with no reserve and a quota above 1 GiB and at most 2 GiB. A 2 GB Disk Utility quota fits. Mount and unlock it, enable ownership and create an owner-only cache directory if needed. The mount targets a 1 GiB read cache inside the volume. Enable FileVault for the Mac system disk. [Apple APFS quotas](https://support.apple.com/guide/disk-utility/dskua9e6a110/mac)

```bash
sudo diskutil enableOwnership /Volumes/ProjectDriveCache
sudo install -d -m 0700 -o "$(id -un)" /Volumes/ProjectDriveCache/cache
```

Copy `config/mac.json.example` to `config/mac.local.json`. Use the Terraform bucket endpoint, Mac role ARN and mount profile name. Keep `db_host` as `127.0.0.1` for the Mac-hosted index. Use the host's private tailnet address when using the optional hosted index.

Initialize once per filesystem, then mount it in Finder.

```bash
bash scripts/client-mac.sh initialize
bash scripts/client-mac.sh mount
```

The mount opens at `~/Cloud Storage`. Drag it into Finder Favorites for a shortcut. Write-back and same-bucket metadata dumps are disabled. To reconnect, close any open files, run `bash scripts/client-mac.sh status` and unmount the previous mount with `bash scripts/client-mac.sh unmount` if needed. Use `mount` again when the index and AWS sign-in are available.

## Add Windows

Use the two-role Terraform configuration. If the index runs on the Mac, run `bash scripts/index-mac.sh password windows` to enable the Windows database login with its own password.

Install Tailscale on both devices. Merge the Windows-to-Mac TCP 55432 entry in the example policy using your real tailnet addresses. Use the proof cases in the example to check access from the approved Windows peer and denial from an unapproved peer. With the hosted option, grant both clients TCP 55432 to that host. Broad grants and ACLs are additive. [Example policy](../config/tailnet-grants.hujson.example) · [Tailscale grants](https://tailscale.com/docs/reference/syntax/grants)

Enable a tailnet-only Serve forward on the index host. Review existing Serve and Funnel configuration to confirm the port is available. [Tailscale TCP forwarding](https://tailscale.com/docs/reference/tailscale-cli/serve#use-a-tcp-forwarder)

```bash
tailscale serve status
tailscale serve --bg --tcp=55432 tcp://127.0.0.1:55432
tailscale serve status
```

On Windows install Python 3.10+, PowerShell 7.2+, WinFsp 2.1 or later and the official JuiceFS v1.3.3 Windows AMD64 client on PATH. Enable storage encryption for the client cache. Copy `config/windows.json.example` to `config/windows.local.json` and enter the Windows mount profile and role ARN plus the same bucket endpoint. Use the index's Tailscale IPv4 or full MagicDNS name as `db_host`. Set `mac_uid` to the number printed by `id -u` on the Mac. This maps the file owner consistently across the two devices. [WinFsp releases](https://github.com/winfsp/winfsp/releases) · [JuiceFS Windows setup](https://juicefs.com/docs/community/tutorials/windows/)

In a non-elevated PowerShell session, save the Windows database password with user-scoped DPAPI and mount the drive.

```powershell
.\scripts\Use-WindowsDrive.ps1 SavePassword
.\scripts\Use-WindowsDrive.ps1 Mount
```

The default Explorer drive is **Cloud Storage (P:)**. Use the script's `Status` and `Unmount` commands to diagnose or disconnect. Run the [acceptance and recovery checklist](operations.md) before increasing the quota or relying on the mount for important files.

## Optional hosted index

Use the separate Lightsail stack if both devices need independent access. The stack adds a billable Linux instance and a database disk. Inspect the plan and available credits before deploying.

Copy `infra/hosted/project.tfvars.json.example` to `infra/hosted/project.tfvars.json`. Set the same account and Region as the bucket and choose a Lightsail availability zone. Run the same `check`, `plan` and `apply` commands with `--stack hosted --vars infra/hosted/project.tfvars.json`.

On the host install PostgreSQL 16 and Tailscale, then identify the exact empty 8 GiB Lightsail data disk with `lsblk`. The following formats that disk and initializes the private index. Replace the device example with the verified attached disk.

```bash
sudo apt-get update
sudo apt-get install postgresql-16
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT
sudo bash /opt/project-drive/hosted-index.sh prepare-disk /dev/ATTACHED_DATA_DISK --format-empty-disk
sudo bash /opt/project-drive/hosted-index.sh init
sudo bash /opt/project-drive/hosted-index.sh password mac
sudo bash /opt/project-drive/hosted-index.sh password windows
```

Keep PostgreSQL bound to loopback. Add the host to the tailnet, set narrow grants and use the Serve command above. If the S3 filesystem already exists, stop all current mounts, export the index and make a native file backup. Stop the original index, restore the PostgreSQL archive with `hosted-index.sh restore` and update both client configs and passwords. Use exactly one writable index for the volume. For a fresh deployment, initialize the filesystem once against the hosted index. [Lightsail pricing and disk snapshots](https://aws.amazon.com/lightsail/pricing/)
